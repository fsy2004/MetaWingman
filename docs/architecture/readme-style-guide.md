# README 风格标准（2026-08-17 定稿，之后所有自述文件按此更新）

适用：本人名下所有对外代码仓库（MetaWingman、bioinfo-reusable-code 等）。

## 1. 双语结构：先全英文，后全中文

- 英文部分在前、中文部分在后，中间用 `---` 分隔，中文部分以
  `## 中文说明` 开头，不交替混排。
- 两部分内容对等（同一信息两种语言），不是摘要关系。
- 模块级 README 保持现状（以中文为主、少数英文），首页英文部分如实
  注明这一事实并指向索引。
- Badge 的显示文本语言跟随所在部分（英文部分英文 badge，中文部分
  中文 badge）。

## 2. 语气：参照主流开源仓库

- 以**从未接触过本项目的人**的视角从头描述：只写项目本身是什么、能做什么、
  怎么用、现状与文档入口；不出现内部对话痕迹、内部政策宣言、运维细节
  （如网络代理、同步通道）、研发叙事（如"北极星""对标顶刊"）与内部审计
  台账式章节。
- 开头是项目名 + 一句话 tagline（是什么、解决什么问题）。
- 面向使用者（"you"），不用"我们"；短段落、bullet 化；命令即用即走。
- 无营销腔、无感叹、无"强大/全面"类形容词堆砌；用事实列表代替。
- 信息密度优先：每个小节先给结论，细节进链接。

## 3. 结构模板（顺序固定）

1. Title + tagline
2. Badges（shields.io）
3. What it is（是什么、为什么）
4. 现状/状态（如实分级，有几分证据写几分）
5. 特性 / 交付物
6. 快速开始 / 安装（最小可复现命令）
7. 使用说明
8. 文档链接
9. License

## 4. Skill 的定位写法

- 统一表述：skill 天然**跨 LLM 通用**（model-agnostic / host-agnostic），
  跑在用户已有的宿主模型上，不绑定任何厂商或 API、不要求额外模型
  API 账号。
- 具体封装（如 Codex plugin）只作为"封装形式之一"出现，不作为定位。
- 不再使用"面向 Codex 的 skill"这类表述。

## 5. 事实边界

- 数字只引用实际输出与 receipt，不夸大；弱标签/开发集/未端到端验证
  等限定词必须保留。
- 不写未经执行的声明（如"已在某主机验证"）。
- 相对链接在提交前确认目标存在。

## 6. 维护

- 项目现状、数字、链接变化时同步更新 README 两部分（英+中）。
- 提交信息格式：`docs: update README (bilingual)`。
