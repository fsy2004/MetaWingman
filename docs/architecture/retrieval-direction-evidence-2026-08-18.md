# 检索方向实证结论（2026-08-18）：词法召回为当前最优，模型定位重排

全部数字来自服务器实测（dev 10,882 查询 × 10,882 文档，family-masked，
正样本 = dev_examples[i].input_text；receipt 文件
`/root/autodl-tmp/{zero-shot-base-retrieval,bm25-baseline}.json`）。

## 1. 全库检索对比（MRR / R@10 / P@1）

| 检索器 | MRR | R@10 | P@1 |
|---|---|---|---|
| **BM25（k1=1.5, b=0.75）** | **0.294** | **0.382** | **0.247** |
| TF-IDF | 0.220 | 0.315 | 0.170 |
| 12k 微调模型（V3） | 0.0045 | 0.0060 | 0.0006 |
| 未微调 BiomedBERT 基座（零样本） | 0.0030 | 0.0048 | 0.0009 |

## 2. 结论（证据链）

1. **110M BiomedBERT CLS 双编码器没有开放检索能力**：未微调基座 0.0030 与
   微调后 0.0045 均在噪声级——微调（1 正 + ≤3 硬负目标）只建立了候选集判别
   （0.962），从未建立语料级区分。这不是微调损害，是基座+目标的双重限制。
2. **词法检索是当前最优召回层**：BM25（0.294）> TF-IDF（0.220），且零训练、
   零 GPU。两段式实验（two-stage-retrieval-results-2026-08-18.md）已证明
   12k 重排器在 50-200 真实候选上呈负贡献。
3. **实用配置（当前最优）**：开放检索用 **BM25**；12k 模型用于小候选集判别
   场景（对选择、验证、硬负区分——0.962）。不再把 110M 模型当召回器。

## 3. 突破 0.294 的路径（按证据排序）

1. 专用检索基座（BGE-M3 / ColBERT 类，语料级对比学习）做召回层 +
   12k 模型重排——需要下载/微调新基座，GPU 工作量中；
2. 在 110M 模型上重训"语料级 in-batch 负样本"目标——基座零样本 0.0030 的
   证据表明上限存疑，不优先；
3. 混合词法（BM25 + 稀疏扩展检索 SPLADE）——折中。

## 4. 对"训练要大"的修正

训练扩量（27k 全量）对候选集判别可能仍有增益（标签更多），但对全库召回
不改变根本限制。扩量训练前先定检索架构（BM25 召回 + 候选集模型已可用）；
GPU 预算优先投给"评价步骤验证器/纳排分类器"等候选集型组件（它们处于模型
能力的甜点区 0.96-0.99），而非重复检索组件。
